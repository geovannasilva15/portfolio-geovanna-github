01 / CASE STUDY · Generative AI and media literacy

Proof Before Post

A bilingual experience for reviewing claims, examining sources and documenting editorial decisions before publishing content.

Open live demo ↗View code on GitHub ↗
Live demoNext.js 16React 19TypeScriptOpenAI Responses API
01 / Context

The problem behind the project

Content creators need to evaluate claims and sources before publishing, but they do not always have a clear process for documenting that review. This project turns that responsibility into a guided, repeatable workflow.

02 / Product

What I built with the team

Guided reviewEnter text or a public URL, select claims and compare supporting evidence.
Verifiable sourcesOrganize up to three sources with metadata and assess how each relates to a claim.
Evidence ReceiptDocument the editorial process and export the record as PDF, PNG or text.
Accessibility and languagesPortuguese and English interface, browser-based narration and keyboard navigation.
03 / Workflow

How the solution works

  1. 01
    Start with the claimEnter a draft, publication or public URL and identify what needs verification.
  2. 02
    Examine the sourcesCompare evidence and record what it actually supports, including uncertainty and limitations.
  3. 03
    Make an informed decisionThe user decides how to revise the content and documents the review in the Evidence Receipt.
04 / Engineering

What the code demonstrates

The application uses Next.js and TypeScript, integrating the OpenAI Responses API. The repository includes product tests and end-to-end flows with Playwright, along with controls for importing URLs and exporting results.

05 / Transparency

Current stage and limitations

The Evidence Receipt documents a review process; it is not a certificate of truth. Editorial decisions remain human responsibilities. The image above was rendered from the interface source code because a screenshot of the live environment was not available when this case study was prepared.
